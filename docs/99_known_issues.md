## ✅ 의도된 설계 · 마지막 실행 기준 정상 (2026-11-17 사용자 진술)
> F15·F3·F17은 지금 실행해서 확인한 것이 아니라 **마지막으로 실행했을 때의 기억**이다. 다음에 서버를 띄울 때 리허설 체크리스트(아래 8번)로 재확인한다.

| ID | 사용자 진술 | 문서 처리 |
|---|---|---|
| F16 | 통계에 `BIG5`가 함께 집계되는 것은 **의도한 설계** (MBTI 유형과 Big Five를 한 통계에서 비교) | 버그 목록에서 제외, [02](02_database.md)·[09](09_ui_screens.md)에 설계로 기록 |
| F15 | Big Five에서 마당 선택이 정상 동작했던 것으로 기억 | 보류 — 재확인 필요 |
| F3 | 결과 화면 새로고침이 정상이었던 것으로 기억 | 보류 — 재확인 필요 (세션 없이 접속하는 경우는 별개) |
| F17 | 통계 상세 막대가 정상이었던 것으로 기억 | 보류 — 재확인 필요 |

> ⚠️ **확인이 필요함 — 로컬 사본과 서버 코드의 차이**: F15·F17은 로컬 사본(`app.py`, `Ani_in.html`, `bigfive_ai_server.py`, 수정일 2026-11-05)의 코드에서 발견한 것이다. 시연에서 정상이라면 **서버의 코드가 로컬 사본보다 최신**일 가능성이 높다. 졸업작품 제출물과 이 문서가 서버 버전과 일치하도록 **서버 코드를 로컬로 다시 복사**하는 것을 권장한다.
> 참고로 화면만으로는 구분이 어려운 경우가 있다.
> - F15: 마당 값은 결과 화면에 그대로 표시되므로, 서버 내부 점수에 반영됐는지는 리포트 **8번 "마당 활용 및 산책 조언" 문구**가 "마당 인프라…"(있음)로 나오는지로 확인할 수 있다.
> - F3: 새로고침이 아니라 **세션이 없는 상태**(로그아웃 후, 또는 새 브라우저에서 `/result_big5`로 직접 접속)에서만 발생하는 경로다.

## 🔴 B. 심사·질의응답 대비 (코드보다 "설명"이 중요)

| ID | 예상 질문 | 현재 상태 | 권장 대응 |
|---|---|---|---|
| F1-b | **"MBTI와 추천 결과가 실제로 어떤 관계가 있나요?"** | 학습 데이터에서 MBTI를 무작위로 뽑아 정답과 관계가 없음 → 현재로선 답하기 어려움 | ① 발표의 메인을 **Big Five(수치 기반, 설명 가능)**로 두고 MBTI는 "선호·환경 기반 추천"으로 소개, 또는 ② MBTI 4축 → 기질 매핑 규칙을 간단히 정의하고 데이터를 다시 생성해 재학습 (1~2일) |
| F1 | "LLM 출력이 잘 나오나요? 실패율은?" | 학습 템플릿과 서빙 프롬프트가 달라 fallback 빈도가 높을 것으로 추정 | 서빙 프롬프트를 학습 템플릿에 맞춤(재학습 없음) → **수정 전후 JSON 성공률을 100회씩 측정해 발표 자료에 수치로 제시** (정량 지표 확보) |
| F1-c, F1-d | "학습 데이터는 어떻게 만들었나요?" | Big Five는 학습 과제(품종 선택)와 서빙 과제(설명만)가 다르고, 동물 종류 칸에 품종이 들어간 데이터 | 발표에서는 "규칙 기반으로 고르고 LLM은 설명만 생성하는 하이브리드 구조"로 설명. 재학습할 여유가 있으면 설명 전용 데이터로 |
| B4 ([04](04_bigfive_ai_server.md)) | "개의 개방성(O)은 어떻게 정의했나요?" | 낯선사람 친화력 + 훈련용이성 | 근거 문헌 1~2개를 찾아 두거나 "자체 정의한 가정"이라고 분명히 밝히기 |
| Q16 | (발표 직전 서버 장애) | v3 어댑터와 MBTI 학습 데이터가 리눅스 서버에만 있음 | **발표 전에 반드시 로컬·클라우드에 백업** — 문제가 생기면 복구할 방법이 없음 |

## 🟠 C. GitHub·포트폴리오로 공개할 때만 필수
런칭하지 않더라도 **공개 저장소에 올리면 키는 몇 분 안에 자동 수집된다** (Gemini 과금, Gmail 스팸 발송에 악용). 공개하지 않으면 우선순위가 낮다.

| ID | 내용 | 조치 |
|---|---|---|
| S1 | API 키·OAuth secret·Gmail 앱 비밀번호·DB 비밀번호가 평문 | ✅ **2026-11-17 적용**: `app.py`·`db_config.py`의 키 14개를 `.env`로 분리, `.env.example` 작성, `.gitignore`로 `.env`·`test.py`·`__pycache__`·백업 파일 제외. 업로드 대상 102개 파일에 키 0건 확인. **이미 다른 곳에 올린 적이 있다면 키 재발급** |
| Q13, Q14 | 구버전·쓰레기·바이너리 파일 | ✅ `.gitignore`로 제외 (로컬 파일은 그대로 남아 있음) |
| Q11 | `GeminiDB.sql`이 실제 DB와 다름 | 보고서에 ERD를 넣는다면 실제 DB에서 DDL을 다시 추출 |

## 🟡 D. 시연 방식에 따라 선택
| ID | 내용 | 판단 기준 |
|---|---|---|
| S2 | `debug=True` | **로컬 시연**이면 그대로 둬도 됨. 터널로 외부에 공개하거나 에러 화면(traceback)이 발표 화면에 뜨는 게 싫으면 `False` |
| S4 | Gemini 대화 기록을 모든 사용자가 공유 | 시연자 혼자 쓰면 문제없음. 심사위원이 각자 휴대폰으로 접속하면 대화가 섞임 → 수정이 쉬우므로(`generate_content`로 교체) 고치는 것을 권장 |
| Q2 | 제외 품종을 부분 문자열로 매칭 | 재추천 결과가 이상하게 좁아질 때만 |
| Q4, Q12 | 효과 없는 설정값, 쓰지 않는 변수 | 코드 리뷰를 받는다면 정리 |
