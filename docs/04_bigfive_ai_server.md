# 04. Big Five 추천 AI 서버 (`bigfive_ai_server.py`)

## 개요
| 항목 | 내용 |
|---|---|
| 실행 | `uvicorn` 0.0.0.0:**8001** |
| 엔드포인트 | `POST /recommend_bigfive` (`async`, `ThreadPoolExecutor(max_workers=2)`) |
| 모델 | 같은 llama3_model (4bit) + LoRA `/home/soulpow_2121/trained_bigfive_expert_v3` |
| 데이터 | `/home/soulpow_2121/더블체크_품종/SoulPaw_Final_Dataset_v1plus.csv` (이 폴더에는 없음) |
| 호출하는 곳 | Flask `/Animalbeer/bigfive`, `/Animalbeer/re_recommend` |

**설계 포인트**: 품종은 **규칙 기반 수치 매칭**으로 고르고, LLM은 **설명문만** 쓴다. 그래서 MBTI 서버보다 결과가 안정적이다.

## 입력 `BigFiveInput`
`O, C, E, A, N` (float, 0~1), `environment`, `yard` (`있음`/`없음`), `exclude: list[str]`

## 1단계 — 품종 성향 점수 (서버 시작 시 CSV로 계산)
CSV 컬럼(1~5점): 에너지, 놀이욕구, 훈련용이성, 아이들친화력, 다른개들과 친화력, 낯선사람과 친화력, 경계성, 짖음, 털빠짐, 유전병, 초보자가이드, 품종

| 품종 차원 | 계산식 |
|---|---|
| E | (에너지 + 놀이욕구) / 2 / 5 |
| A | (아이들 + 다른개 + 낯선사람 친화력) / 3 / 5 |
| C | (훈련용이성 + (6 − 짖음)) / 2 / 5 |
| N | (경계성 + 짖음) / 2 / 5 |
| O | (낯선사람 친화력 + 훈련용이성) / 2 / 5 |

### 주거 적합도 (기본 1.0에서 감점)
| 조건 | 아파트 | 빌라 | 마당필요도 |
|---|---|---|---|
| (짖음+경계성)/2 ≥ 4 | −0.4 | −0.3 | |
| (짖음+경계성)/2 ≥ 3 | −0.2 | −0.1 | |
| E > 0.75 | −0.4 | | +0.8 |
| E > 0.60 | −0.2 | | +0.4 |
| 털빠짐 ≥ 4 / ≥ 3 | | −0.3 / −0.1 | |
| 하한 0.1, 단독주택은 항상 1.0 | | | 상한 1.0 |

## 2단계 — 추천 (`recommend`)
1. `exclude` 품종 제외 (공백·괄호·슬래시 제거 후 비교). 남는 게 없으면 전체 사용
2. 점수 = `1 / (유클리드거리(사용자 OCEAN, 품종 OCEAN) + 0.05)`
3. × 주거 적합도 (아파트/빌라)
4. 마당이 없고 마당필요도 ≥ 0.6이면 × (1 − 마당필요도 × 0.4)
5. **상위 10개 중 점수에 비례한 확률로 1개 추출** → 같은 입력이라도 결과가 다를 수 있음

## 3단계 — 매칭 리포트 (`compile_detailed_reason`, 규칙 기반)
| 항목 | 분기 |
|---|---|
| E | 차이 ≤ 0.2이면 "동기화" / 사용자가 더 높으면 "정서적 안식처" / 품종이 더 높으면 "페이스메이커" |
| A | 품종 A ≥ 0.7이면 높은 사회성, 아니면 독립적 성품 |
| C | 훈련용이성 ≥ 4이면 교육 용이, 아니면 칭찬 중심 교육 |
| 소음 | 아파트·빌라에서 (짖음+경계성)/2 ≤ 2.5이면 안전, 아니면 초기 소음 교육 권장 |

## 4단계 — LLM 소견 (`generate_description`)
- 입력: 품종, 외형(털·크기), 주거, 매칭 리포트
- 출력 JSON 키: `reason`, `warning`, `environment_fit`, `guide`
- 설정: `max_new_tokens=550`, `do_sample=False` (greedy 결정적 생성. `temperature`·`top_p`는 무시됨), `repetition_penalty=1.1`
- 파싱: 정규식 `\{.*\}`(탐욕적 매칭) → 실패하면 기본 문구

## 하드코딩 데이터
- `size_map`: 개 53품종의 크기 구분(대·중·소형견), 체중·체고 범위 (`coat_map`도 53품종, CSV의 53품종과 정확히 일치)
- `coat_map`: 털 길이 (장모·중모·단모·특수모)
- CSV에는 있는데 맵에 없는 품종은 `중형견` / `단모종`으로 처리한다 (현재는 해당하는 품종이 없음. CSV에 품종을 추가할 때 맵도 함께 갱신해야 함)

## 응답 (9개 항목 `full_text`)
1 동물 종류(항상 `강아지`) · 2 품종 · 3 빅파이브 매칭 보고서 · 4 전문가 소견 · 5 유전 질환(LLM + CSV) · 6 주거 환경 · 7 외형(털·크기·체중·체고) · 8 마당·산책 조언 · 9 양육 가이드(LLM + CSV)
추가 필드: `score` (점수 × 10)

## 문제점
| # | 내용 |
|---|---|
| B1 | `max_workers=2`로 모델 1개에 `generate`를 동시에 2건 실행 → GPU 경합·OOM 위험. RTX 4070 12GB에 MBTI 서버까지 함께 떠 있는 상황이라 특히 위험하다. 1로 줄이거나 큐를 두는 게 안전 |
| B2 | 주거 적합도 루프가 `row["짖음"]`, `row["털빠짐"]` 원본 값을 사용 (`safe_num` 미적용). 현재 CSV에는 결측이 없어 문제가 없지만, 데이터를 갱신할 때 NaN이 들어오면 점수가 틀어지는 잠재 버그 |
| B3 | 동물 종류가 `강아지`로 고정 → 개 외의 동물은 추천 불가 |
| B4 | O(개방성)를 "낯선사람 친화력 + 훈련용이성"으로 정의 — 심리학적 근거가 약함. 문서·발표에서 설명이 필요한 가정 |
| B5 | `\{.*\}` 탐욕적 매칭 → 중괄호가 여러 번 나오면 파싱 실패 |
| B6 | `.to("cuda")`와 `device_map="auto"`를 섞어 씀 |
